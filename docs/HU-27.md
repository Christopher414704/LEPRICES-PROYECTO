# HU-27 — Estimar consumo del vehículo

Estado: implementada. Aplicar la migración `0020_estimar_consumo_vehiculo.mjs` antes de usarla.

## Uso

En **MiAutomóvil → Mi garaje**, cada vehículo muestra **Consumo estimado**. Cuando su ficha guardada contiene consumo combinado en `L/100 km`, se usa esa referencia sin volver a consultar al proveedor. La pantalla identifica el origen y expresa el resultado en **L/100 km** y **km/L**.

En **Usar mis datos de consumo**, el conductor registra kilómetros recorridos y litros consumidos durante el mismo intervalo. Al medir con recargas, debe usar el método de tanque lleno a tanque lleno. El kilometraje inicial del garaje es un odómetro y no se usa como distancia recorrida.

La última medición guardada tiene prioridad sobre el catálogo y puede actualizarse o eliminarse. Al eliminarla vuelve la referencia del vehículo, si existe. Cada vehículo tiene su propia medición; el catálogo compartido y los demás vehículos no se modifican. La medición se elimina automáticamente al quitar el vehículo del garaje.

Si faltan tanto medición propia como consumo combinado válido, se indica **No hay información suficiente** y se permite registrar datos propios. No se deduce consumo de marca, modelo, cilindrada ni promedios de ciudad/carretera. No se interpretan MPG o MPGe como litros; las fichas de FuelEconomy ya se normalizan a L/100 km en el registro existente. En vehículos cuyo combustible principal es electricidad se indica que el consumo en litros no aplica.

## Cálculo y reutilización en rutas

Para una medición personal:

```text
litrosPorKm = litros / distanciaKm
consumoL100Km = litrosPorKm × 100
rendimientoKmLitro = 1 / litrosPorKm
```

Para catálogo, `litrosPorKm = ficha.consumo.combinado / 100`. La API conserva la precisión numérica para futuros cálculos; el redondeo de dos decimales solo se aplica al mostrar el resultado. Valores positivos menores que 0.01 se muestran como “menos de 0.01” para evitar mostrarlos como cero.

Ejemplo: 400 km y 32 litros dan **8 L/100 km**, **12.5 km/L** y **0.08 L/km**. El módulo de rutas podrá consultar esta API y calcular `litrosEstimados = distanciaRutaKm × litrosPorKm` únicamente si `disponible === true`. La integración con el módulo de rutas queda para esa historia; aquí se proporciona el dato reutilizable.

## API, validación y permisos

- `GET /api/mi-automovil/vehiculos/:id/consumo`: estimación del vehículo registrado. Responde `200`, también cuando no hay información suficiente (`disponible: false`, valores numéricos `null` y motivo explícito).
- `PUT /api/mi-automovil/vehiculos/:id/consumo`: guarda/reemplaza la medición con `{ "distanciaKm": 400, "litros": 32 }` y devuelve la estimación en `data`.
- `DELETE /api/mi-automovil/vehiculos/:id/consumo`: elimina la medición personal y devuelve la estimación basada en la información restante. Puede repetirse sobre un vehículo existente.

La respuesta incluye `idVehiculo`, `disponible`, `motivo`, `mensaje`, `fuente` (`usuario` o `catalogo`), `unidad`, `consumoL100Km`, `rendimientoKmLitro`, `litrosPorKm`, `datosUsuario` y `referencia`. `datosUsuario` identifica distancia, litros y fecha de actualización; `referencia` identifica proveedor y ciclo combinado. No se almacena un resultado calculado que pueda quedar desactualizado respecto a los datos base.

Se exige sesión y rol conductor. Todas las consultas y mutaciones filtran por vehículo **y propietario de la sesión**, incluso la inserción. Las escrituras exigen el origen autorizado; las respuestas usan `Cache-Control: no-store`. La ficha y el propietario no se aceptan desde el cuerpo del cliente.

Se validan identificadores positivos y medidas mayores que cero con hasta dos decimales: máximo 1,000,000 km y 100,000 litros. No se aceptan ceros, negativos, booleanos, objetos, unidades ambiguas ni notación exponencial en cadenas. La base también aplica restricciones de valor y una clave única por vehículo. Errores: `400` datos inválidos o litros para un eléctrico, `401` sin sesión, `403` rol/origen no autorizado y `404` vehículo inexistente o ajeno.

## Migración y pruebas

Desde la raíz:

```sh
pnpm --filter @jalapa/api db:migrate
pnpm test
pnpm --filter @jalapa/web build
```

La migración agrega únicamente `consumo_personal_vehiculo`; su reversión elimina esas mediciones, conservando vehículos y fichas. Para activar la prueba real de HU-27 en PowerShell:

```powershell
$env:RUN_HU27_DB = "1"
pnpm --filter @jalapa/api test
```

También se activa con `RUN_DB_TESTS=1`. Usa un esquema temporal para verificar persistencia, prioridades, aislamiento entre cuentas, actualización, eliminación, restricciones SQL y reversión/reaplicación de la migración.
