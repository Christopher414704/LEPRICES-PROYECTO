# HU-20 – Cargar gasolineras desde PostgreSQL

## Fuente del catálogo

PostgreSQL es la única fuente de información del catálogo durante la ejecución. `GET /api/gasolineras` utiliza el repositorio de gasolineras, que consulta las tablas `gasolineras`, `marcas`, `combustibles_gasolinera`, `tipos_combustible`, `precios_combustible` y `modalidades_servicio`.

La consulta excluye las estaciones inactivas y la respuesta incluye, entre otros datos, `id`, `nombre`, `codigo` y `ubicacion.latitud`/`ubicacion.longitud`. El endpoint requiere una sesión válida conforme a las reglas de seguridad existentes.

## Frontend

El mapa interno solicita `GET /api/gasolineras`; el mapa público utiliza la variante pública filtrada `GET /api/publico/gasolineras`. Ambas respuestas se procesan con el mismo cargador remoto y cada elemento recibido genera o actualiza su marcador dinámicamente.

No existe un catálogo fijo dentro de `apps/web`. Los datos de Jalapa que se conservan en `apps/api/scripts/catalogo-jalapa.datos.js` sirven únicamente para una carga inicial explícita de PostgreSQL y nunca forman parte del bundle ni se importan desde el frontend.

Los mapas abiertos vuelven a consultar el catálogo cada 30 segundos y al recuperar el foco. Por ello, una estación registrada en PostgreSQL aparece sin modificar ni recompilar el código. Si la API falla o devuelve un formato inesperado, el mapa conserva su estado y muestra un mensaje de error controlado.

## Verificación

- Pruebas de API para el contrato del catálogo y la delegación de errores de PostgreSQL.
- Pruebas web para los endpoints usados, filtros, caché y respuestas inválidas.
- La prueba de integración PostgreSQL registra una estación y verifica que aparezca inmediatamente en el catálogo consultado.
