# HU-11 — Registrar nueva gasolinera

Los administradores tienen la opción **Registrar estación** en el mapa interno. El formulario solicita nombre, marca activa, dirección, municipio, departamento, latitud y longitud. Al guardar, abre la estación en el mapa. Las estaciones se publican sin precios ficticios; los mapas abiertos actualizan el catálogo cada 30 segundos mientras la página está visible, y al recuperar el foco.

## API y permisos

- `GET /api/gasolineras/marcas`: marcas activas para el formulario; requiere administrador.
- `POST /api/gasolineras`: registra una estación; requiere sesión de administrador y origen autorizado.
- `GET /api/gasolineras` y `GET /api/publico/gasolineras`: incluyen las estaciones registradas.
- Respuestas del registro: `201` éxito, `400` datos inválidos, `401` sin sesión, `403` sin permisos/origen autorizado, `409` duplicado.

Ejemplo del cuerpo de registro:

```json
{
  "nombre": "Gasolinera Nueva",
  "idMarca": "1",
  "direccion": "Calle principal, zona 1",
  "municipio": "Jalapa",
  "departamento": "Jalapa",
  "latitud": "14.635000",
  "longitud": "-89.990000"
}
```

La marca debe existir y estar activa. El país es Guatemala. La latitud debe estar entre −90 y 90, y la longitud entre −180 y 180; se almacenan con seis decimales, conforme al esquema existente. Los campos vacíos, valores no numéricos y coordenadas fuera de rango se rechazan en el servidor.

## Duplicados y auditoría

La migración `0011_registrar_gasolineras_y_auditoria.mjs` añade restricciones únicas en PostgreSQL:

1. Nombre normalizado + municipio normalizado + departamento normalizado. La comparación ignora mayúsculas, tildes y espacios repetidos.
2. El par latitud/longitud almacenado con seis decimales.

Estas reglas también cubren solicitudes concurrentes y estaciones inactivas. El código público se genera con UUID. La migración falla si existen datos previos que infringen las reglas; deben revisarse antes de aplicarla, sin eliminar registros automáticamente.

El registro y su auditoría se confirman en una misma transacción. `auditoria_gasolineras` conserva la estación, el usuario autenticado, la operación, la fecha y una copia JSON de los datos registrados. Si falla la auditoría, la estación no se guarda. El servidor vuelve a comprobar que el administrador y su rol siguen activos antes de insertar.

## Aplicación y verificación

Desde la raíz del repositorio, con los archivos `.env` configurados y PostgreSQL/PostGIS disponible:

```sh
pnpm install --frozen-lockfile
pnpm --filter @jalapa/api db:migrate
pnpm test
pnpm --filter @jalapa/web build
```

Las pruebas con PostgreSQL se activan con `RUN_DB_TESTS=1`; utilizan esquemas temporales. En PowerShell:

```powershell
$env:RUN_DB_TESTS = "1"
pnpm --filter @jalapa/api test
```

La nueva suite comprueba validación, permisos HTTP, origen autorizado, publicación en la API pública, coordenadas PostGIS, auditoría, duplicados concurrentes y reversión de la estación cuando falla la auditoría.
