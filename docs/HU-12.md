# HU-12 — Editar información de una gasolinera

El administrador accede a **Editar estación** desde el mapa interno o desde el registro de gasolineras. Selecciona una estación activa y el formulario carga su nombre, dirección, municipio, departamento, latitud y longitud. Al guardar recibe **Gasolinera modificada correctamente** y puede abrir la estación actualizada en el mapa.

## API y validación

`PUT /api/gasolineras/:id` requiere una sesión de administrador y un origen autorizado. El servidor vuelve a comprobar que el usuario y su rol estén activos dentro de la transacción. Los gestores de precios y los usuarios de consulta no pueden editar datos de las estaciones.

Ejemplo de actualización completa de los campos editables:

```json
{
  "nombre": "Gasolinera Central",
  "direccion": "Avenida principal, zona 2",
  "municipio": "Jalapa",
  "departamento": "Jalapa",
  "latitud": "14.636900",
  "longitud": "-89.986700"
}
```

Todos esos campos son obligatorios. Se validan los mismos límites de longitud y coordenadas de la HU-11: latitud entre −90 y 90, longitud entre −180 y 180, almacenamiento con seis decimales. El identificador debe ser un entero positivo. Se mantienen las restricciones únicas de nombre normalizado por municipio/departamento y del par de coordenadas; conservar los datos de la propia estación no constituye un duplicado.

Respuestas: `200` éxito con mensaje y datos actualizados; `400` datos inválidos; `401` sin sesión; `403` permisos u origen no autorizado; `404` estación inexistente/inactiva; `409` duplicado. El formulario conserva los datos ingresados si falla la actualización.

## Persistencia, auditoría y mapa

La estación se bloquea con `FOR UPDATE` mientras se modifica. La actualización y el registro de auditoría se confirman juntos en PostgreSQL. Si falla cualquiera, ambos se revierten. La auditoría guarda operación `edicion`, estación, administrador autenticado, fecha y JSON con `antes` y `despues`. Las ediciones simultáneas producen una secuencia coherente de valores anteriores y nuevos.

Se conservan el identificador, código público, marca, país, publicación, combustibles, precios e historial. Las coordenadas actualizan automáticamente la ubicación PostGIS mediante la columna generada existente. Los listados internos y públicos consultan los datos modificados.

Los mapas abiertos refrescan el catálogo cada 30 segundos mientras están visibles y al recuperar el foco. Ahora actualizan también el nombre, etiqueta y posición de los marcadores existentes. Una respuesta de precios pendiente o almacenada en memoria conserva el nombre y la ubicación del catálogo más reciente, evitando volver a mostrar información anterior a la edición.

## Migración y pruebas

Con PostgreSQL/PostGIS disponible y la configuración `.env` existente, ejecutar desde la raíz:

```sh
pnpm --filter @jalapa/api db:migrate
pnpm test
pnpm --filter @jalapa/web build
```

La migración `0012_auditar_edicion_gasolineras.mjs` permite operaciones `registro` y `edicion` en la auditoría. Su reversión conserva las auditorías históricas de edición y restringe las nuevas operaciones a `registro` mediante una restricción `NOT VALID`.

Para ejecutar las pruebas reales de PostgreSQL en PowerShell:

```powershell
$env:RUN_DB_TESTS = "1"
pnpm --filter @jalapa/api test
```

La suite de integración utiliza un esquema temporal y añade comprobaciones de ubicación PostGIS, consulta pública, conservación de precios, duplicados, edición concurrente y reversión por fallo de auditoría.
